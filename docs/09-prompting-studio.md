# 怎么给 Studio 提需求

实测环境：StepX Neo · Step AOS 1.0.0.2 · 2026-11-10

下面是我们做了几个 Studio 应用后总结的写法。Studio 一轮生成要十几到几十分钟，需求写清楚比事后返工划算得多。

## 先问一轮"只回答、不写代码"

新项目的第一轮，不让它写代码，只问"能不能做"。

我们做背屏应用前，第一轮问了 7 个问题：能不能设系统壁纸、能不能存相册、打开别的应用时能不能传参、插件能不能扩展原生能力、调用背屏会不会弹授权、能不能连续推帧做动画、能不能出包上架。Studio 两分钟就答完，每条给了结论，拿不准的会明确写"不确定"。这一轮让我们没有白做一个根本实现不了的壁纸功能。

问法要点：

- 开头写明"这一轮只回答问题，不要写代码"。
- 问题编号，一条只问一件事。
- 要求每条先给结论（能 / 不能 / 不确定），再给理由和替代办法。

## 硬性要求写在最前面

不写清楚，Studio 可能会顺手加上后端、登录、模拟数据。我们每次都在开头放一段"硬性要求"，大意是：

- 不要后端、数据库、登录、埋点、支付、管理后台，只要手机端这一个构建目标，数据只存本机。
- 所有能力调用都是真实调用，不能用模拟数据顶替。在网页预览里运行时，顶部提示"请在手机上使用"，界面照常展示。
- 调用失败时先给用户一句看得懂的话，下面可以展开看原始错误码和错误信息，不要改写成"出错了请重试"。
- 界面用中文。

## 把容易错的细节写死

涉及手机能力的地方，把数据格式和规则直接写进需求，不要让它猜。比如背屏：画布 17 × 23，一帧是 391 个 0–255 的数，下标 y × 17 + x；清除要用清除能力，不能推全零帧；实时同步两次推送至少隔 300 毫秒。

## 一次只改一个方向

第一版做完后，每轮只改一件事。我们改成像素风那一轮，开头就写"方向调整"，列出范围变化，并写明"已经做好的不要删，只改视觉"，同时重申之前的硬性要求继续有效。一轮里既改功能又改视觉，出了问题很难分清是哪边引起的。

## 让它在最后汇报，并当真

每轮需求的结尾都要它告诉我们：实际用到了哪些能力、声明了哪些权限、哪些只能真机验证。

它列出的"只能真机验证"清单，就是你的真机测试清单。网页预览里一切正常，不代表真机上能用。

## 生成后核对

- 核对项目登记的连接器有没有被增删，见 [踩坑记录](14-pitfalls.md)。
- 长需求粘贴进输入框后，看一眼换行和排版还在不在。Studio 的输入框会合并换行，用编号和小标题写，合并后也还读得懂。
